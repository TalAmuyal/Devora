# The native agent transcript

The transcript is native (ADR-014), its own module (`Packages/TranscriptKit`, whose entry point is `TranscriptView`); the web renderer draws only the guide, the previews and the transcript's Mermaid diagrams.
Its colors are the system's (`TranscriptTheme`: label and secondary label, the accent for links and quote edges, red for errors, separators, and system fills for code, a code block also edged with the separator color), so every row follows the view's effective appearance (the app's Appearance setting, light or dark, and increased contrast) and the user's accent color by themselves; the page is the window's background; the Judgess badges keep their own colors.
A row sits in the conversation by its kind (`TranscriptRow`): the user's message in a system-blue bubble with white text (`TranscriptTheme.onBubble`) at the right, as wide as its text up to 70% of the row (`UserBubbleLayout`, a layout so that the measured height is the bubble's); the agent's reply as text on the page, leaving `replyTrailing` on its right, which with the margins is `replyInset`, the width less which a diagram is drawn; everything else in a grey bubble at the left, tinted red for an error. An interrupted or failed item says so in a caption under it.
Which rows the chat shows is `TranscriptVisibility` (`TranscriptItem.visibility`): always the user's messages, the replies, the model changes, the unsent-prompt marker and errors (`isError`: a failed item, a failure or warning, a turn that ended with one, unless the core marked its result `stopped`); the rest (tools, thinking, the session's notes, unknown items, a turn Devora stopped) as system messages; and never a turn's plain end ("Turn completed"). System messages show only while the chat shows them (`showsSystem`, the chat's setting, hidden by default); `apply` leaves out the rows not shown before laying the rows out, so they're never measured. Permission cards always show. Across an update that drops the reader's top row (hiding system messages), the nearest row above it that stays keeps its place (`keptPin`), else the one below; after a toggle the position is saved again, so it never names a hidden row, and a saved position on a row now hidden opens at the nearest shown row above it.
`TranscriptScrollView` is an `NSTableView` of `TranscriptCell`s hosting SwiftUI `TranscriptRow`s and permission cards, fed `AgentChat.items` and `questions`; `TranscriptChange` turns each update into a prepend, changes in place with rows added or dropped at either end, or a reload.
It follows the bottom while the reader is within 24 pt of it, keeps the top visible row in place otherwise, asks for an older page within 80 pt of the top (saving the anchor first, so the chat stops trimming to its tail), and reports the anchor 250 ms after the reader's scrolls (the item's sequence and its top's offset, or none while following the bottom); its own adjustments don't count as the reader's, nor does a resize: a view following the bottom keeps it through one (the chat's spinner comes and goes under it every turn), and a view that grew pulls its top back to the last one it can show, which no reader can scroll past.
`RowHeights` holds the heights: exact for a row measured at its content and width, otherwise an estimate (its last height, or a guess from its kind and text calibrated by the measurements so far), so `NSTableView` never waits for a measurement.
The table lays a row out at the height it was last given (`tableHeights`), which a measurement is compared with, since an estimate can change after the table took it; and it takes inserted rows' heights at once (`layOut`), since after some batch updates it would otherwise estimate part of them itself and move the rows below later, outside the anchoring, leaving the hosted rows' accessibility frames where the rows were.
The visible rows are measured at once; the rest on idle frames, nearest first, 2 ms a frame, after which the display link stops; a width change makes every height an estimate again; every height change applies without animation and keeps the bottom in place, or else the first visible row that was already exact (so a row scrolled into view settles toward the side not yet seen), or a restored position's row.
Links open only `http` and `https` URLs, never a file or another app's scheme.
Wide code blocks scroll sideways; a mostly vertical scroll gesture over the transcript scrolls the transcript wherever it starts, a code block included, decided once per gesture and kept through its momentum (`WheelRouting`, through a local scroll-wheel monitor that takes only events whose hit test lands in the transcript, so not over a background tab or a layer drawn over it).
A mouse wheel's scroll (XCUITest's too: no phase, no momentum) doesn't move the view when `scrollWheel(with:)` returns: AppKit animates it over the next display frames (about 10 steps in 100–300 ms). Nothing the transcript does in the meantime cancels it (a height correction, `tile`, `reflectScrolledClipView`, a scroll to the same top, a layout); only `reloadData` cuts it short, by jumping to its end. A window that gets no display frames (occluded, off screen, or a runner that draws nothing) doesn't scroll at all, so the wheel trace (`DEVORA_WHEEL_TRACE`) records the frames the window got in the half second after each wheel, and every quarter second the frames it drew (`drawing:`), which the UI test waits on before a wheel.
User, assistant and thinking rows' Markdown is parsed once per content by `MarkdownDocument` (`swift-markdown`) into plain blocks and inline runs that `MarkdownView` draws (a collapsed thought only once it opens).
A Mermaid block is drawn into an image by `MermaidRenderer`, one shared offscreen renderer: a hidden web view on the bundled web renderer (`WebDiagramDrawer`, in an offscreen window at the screen's scale), at the row's width and in colors derived from the view's appearance (`WebRendering`'s `WebPalette`, shared with the web panes: the system's colors as the web renderer's CSS variables, flattened onto the window's background, and `--color-scheme`), which are derived again when the effective appearance or the system's colors (the accent) change (`PaletteFollower`), redrawing the diagrams shown; it draws one diagram at a time (callers waiting for the page are let through together), fails one that doesn't parse or takes over 5 s (dropping the page, so the next starts on a fresh one), starts a fresh page for new colors, and keeps the drawings in a cache bounded by their pixels (48 MB), least recently shown first out.
Until its image arrives a block is a placeholder of a stable height, and the arrival is a height correction like any other (`RowHeights` keys a measurement by a fingerprint of the row's diagrams too); a streaming reply shows the source, and a failed diagram its source under a warning in the error color; a live resize waits for its end to ask for drawings at the new width.
Thinking and tool rows start collapsed: a summary ("Thinking", or the tool's name and its Judgess badge) that a click toggles, keeping the row's top in place; the expansion is the view's, by sequence, so it survives updates, cell reuse and older pages, and `RowHeights` keys a measurement by expansion too.
Each row shows its time (`TranscriptTime`, when its item was first stored, in the user's locale): only the time for today's, the date and time for older ones, and the full date and time as the time's own tooltip; at a user bubble's bottom corner, after a reply's last line (beside its Interrupted or Failed caption), or inline in a grey bubble. A row stored before Devora kept the time shows none. VoiceOver's label carries it after the kind ("You, 10:41").
Each row's hover title shows its sequence, and a reply's also the model that wrote it ("#42 · claude-sonnet-5-5"; none for a reply stored before replies kept it). A model-change row (`SystemKind.modelChanged`) draws as the other system rows; the host words it with the models' names (`TranscriptAdapter`), and VoiceOver reads the `spoken` form its detail carries ("Model changed from Sonnet 5.5 to Opus 5.5"), since an arrow reads poorly.
Each row's context menu has Copy, of the item as written (Markdown included; a tool's name, input and result).
For VoiceOver each row is one element in reading order: its kind and state as the label ("Tool Bash, Judgess approve, collapsed"), its shown text as the value, and Expand or Collapse and its links as actions; a cell the table removed for reuse shows nothing, so it exposes no stale row.
A question is a card, a row of its own that the host builds from `AgentChat.questions` (`TranscriptEntry.layout`, never from an item's content), right after its tool's row or at the end when that row isn't loaded: the tool, its input, the reason, the suggested rules as sentences ("Allow Bash(custom-tool), saved to localSettings"; what a sentence can't say in full stays JSON) with their JSON as the tooltip, and Allow ⌘Y, Deny ⌘N and Always allow ⌘⇧Y (only when it can), which call `AgentChat.answer` with the card's generation, as the keys do.
Rows are keyed by sequence or request id, so a card is diffed, measured and pinned as any row; a saved position is an item's, so a card on top saves the row above it.
The bridge's `GET /test/agent-chat` answers from the native view, under `dom` (`rows` with `chat-<kind>` kinds, the names the scenarios have read since the web transcript, and the time each shows, `cards`, `text` with the cards' text in place, `diagrams` (drawn, failed, pending, or shown as source while streaming), `thinkingOpen`, `toolOpen`, `verdict`, `top`, `topSequence`; nothing native runs content, so markup shows as its text); `toggleThinking`, `toggleTool` and `scrollTop` act on it as the reader would.
