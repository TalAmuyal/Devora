# Agent Spaces

## The restart notice

After a restart, each agent gets one notice to re-establish its waits, since its background work (watchers, builds, CI waits, background shells and subagents) and their notifications don't survive the CLI's stop. Its owner, with the whole lifecycle (owed, attempt, delivered, recovery), is `restart_notice.rs`. The registry makes one `AppRun` per process and passes it to every launch. An agent with a conversation whose CLI last ran in another run owes a notice, which is the first turn its launch admits: a system row (`SystemKind::RestartNotice`) committed with the turn's ID before the send, and cleared by the result naming that ID. Holds, Keep paused and individual pauses only defer it to the agent's launch, and drafts stay untouched. A launch after a notice was cut short reads Claude's saved session (`devora_agent::session::saved_turn`): the entry with that ID means it was delivered, and otherwise it is sent again, marked as a recovery. So delivery is at least once.

A stop that was forced or interrupted a turn (`StopInfo`) also owes the notice, worded for the pause, at the agent's next launch in the same run; a clean, idle stop owes none.

## The agent's compaction threshold

Schema version 5 adds `space.compact_threshold`: the agent's own threshold, over its profile's `agent.compact-threshold`; null follows the profile. The column takes 1 to 100, what was valid before the range (10 to 90, `devora-config::agent::COMPACT_THRESHOLD_RANGE`): `set_compact_threshold` refuses a value outside the range, and one stored before it is used as its nearest limit (`compaction::in_force`), while the context's `own_threshold_percent` keeps it as stored. `SpaceHandle::set_compact_threshold` commits it and applies it at once, through the actor, which owns the database, so it needs a running agent. `SpaceHandle::compact_now` starts the save-memory and `/compact` steps on an idle agent, or flags them for the running turn's result, as reaching the threshold does; a failed or interrupted turn drops that request, as it abandons a compaction. The one exception is a save-memory turn the API refused as too long: from there, and only from there, Devora sends `/compact` anyway, and the refresh after it (`Memory::TooFullToSave`, carried in the compaction's stage, so a reset or an abandoned compaction drops it). Its rows follow Claude Code's own error rows, since the actor stores the result before acting on it; the one saying Devora compacts without the save is a warning (`Step::row_kind`), so a chat hiding system messages still shows it after that error. A `/compact` that fails, other than by the user's Stop (`Transcript::stop_expected`, read before the result spends it), adds a failure row saying so and what to try. The context the actor publishes carries the threshold in force, the profile's (as read at launch), the agent's own as stored (which may equal the profile's, and still pins it), and the compaction's progress (idle, requested, under way).

## Pausing with background work

The actor keeps the agent's background tasks as the CLI lists them (`System::BackgroundTasksChanged`). A pause whose agent has some doesn't close the CLI's input at the turn's boundary: it owes the notice naming them first (so a crash mid-pause still tells the agent), stops each one through the CLI (`stop_task`, shells first), interrupts the notification turn a stopped subagent makes the CLI start, and waits for that turn's result, since once the input is closed nothing can interrupt a turn. Then it closes the input, and the CLI exits by itself (`Preparing` in `running.rs`). Past `PREPARE_GRACE`, or when a task won't stop, the pause goes ahead and the worker's forced stop is the fallback, so at worst a pause takes `PREPARE_GRACE` plus the stop's own grace, about 10 s. An agent with no background work pauses as before, owing nothing. A pause asked of a session the actor has already stopped (its own pause after a turn) answers with the stop the actor recorded, graceful or forced, rather than failing (`RunningSpace::pause`), so a quit racing a hold's pause reports that one stop. A process the agent daemonized isn't a task the CLI tracks, so it outlives the pause (ADR-013).

## The turn running

The actor knows which turn the CLI is running (`ActiveTurn` in `running.rs`, whose comment lists how it moves): one Devora sent (a prompt, the restart notice, a compaction step), or one the CLI started itself, as when a background task reports. Every "between turns" check waits for either: a pause's boundary, telling the CLI a new model, and a compaction the user asked for. The CLI opens each turn with `init`, folds a turn sent during its own into it (one result, answering the turn sent), and folds a background task that finishes during a turn Devora sent into that turn; the pinned-CLI suite asserts all three. A turn the CLI started itself ends on any result, or on the CLI exiting, stopping or failing, so it never outlives its end. The actor publishes it (`AgentTurnStarted`, `AgentTurnEnded`), and the chat shows it running (`Chat.agent_turn`). Its end starts a compaction as the end of a turn Devora sent does (`Compaction::agents_turn_ended`): one the user asked for during it, or the threshold reached, so an agent that works from its background tasks is compacted too; a pause asked for during it wins, as it does after a turn Devora sent.

## A message the agent doesn't have yet

A prompt sent into a turn the agent's CLI started itself waits for the agent's next step (`devora-agent`'s "Where a prompt is"), so its row says so: `TranscriptContent::User::delivery` is `Waiting` from the send (`begin`, on the fold's copy so the row the send's settling upserts keeps it), and cleared when the CLI reports "started" or "completed" for its ID. "cancelled", or the session ending first (a crash: the resumed session never gets it; a pause or a quit doesn't lose it, since the pause's interrupt starts it at once), makes it `NotDelivered`. The delivery is stored with the row, and a launch turns a row still `Waiting` (Devora itself died) into `NotDelivered`. Only a prompt that joined such a turn is marked: one sent otherwise reaches the agent within milliseconds, and a send the CLI never took leaves no waiting row. A prompt sent while no turn was seen running may still join one, when the CLI started its own just before (its `init` not read yet): an idle CLI starts the prompt's turn ("started") before its `init`, so an `init` read while that prompt has no "started" marks it `Waiting` then.

## The running CLI

Schema version 4 adds `space.cli_process`: the running CLI's identity, its pid and start time (`devora_agent::session::CliProcess`, from `SessionEvent::Spawned`, which the space keeps to itself). It is cleared when the CLI ends under Devora's watch. A launch that finds a recorded CLI still running (an earlier Devora died without stopping it) stops its whole tree (`stop_tree`) before resuming, since two CLIs on one session fork it. A pid whose start time differs is another process and is left alone. An orphaned CLI can't run tools meanwhile, since its Judgess callback can't be answered.

## Changing the agent's model

`SpaceHandle::set_model` stores the model with the agent at once (its form's `model`, keeping the effort) and tells the CLI (`SessionHandle::set_model`) only between turns: during a turn, one Devora sent or one the CLI started itself (see "The turn running"), it waits for the turn's end, and a later choice replaces an untold one. `SessionHandle::set_model` queues its request when called, so a turn sent after it runs on the new model even before the CLI answers; the pinned-CLI suite asserts that. A paused agent's model is written straight to its database (`Space::set_model`) and is what it launches with.
The actor publishes `ChosenModel`: what was chosen in this run, whether no reply has come from it yet (cleared by the first main-thread reply after the CLI was told, never by one from the turn that was running, and at once when the CLI refuses it, since a refused model never replies), and why the CLI refused it, if it did; the stored choice stands either way. A relaunch starts without one.
The registry (`devora-core`'s `Agents::set_model`) refuses a model the agent isn't offered (`ModelList::offers`): a running agent's by the list cached for its own launch's settings, a paused one's by the list its next launch would get (`ModelOptions::get`, which asks Claude Code when that isn't cached, so an agent still paused after a restart can be changed too). It refuses while the agent is starting or pausing. A pick Claude Code refuses stays stored: the user decides what to do about it (another model, or a login that has it), and the next launch tries it again.

## Changing the agent's effort

`SpaceHandle::set_effort` works as `set_model` does: the level (none is Claude Code's default) is stored with the agent at once (its form's `model.effort`, keeping the model; `Space::set_effort`, which for an agent created before the model was chosen stores the model it runs too), and the CLI is told between turns of either kind, a later change replacing one not yet told (`SessionHandle::set_effort`). The actor publishes `ChosenEffort`: the level set in this run, whether it's waiting for the running turn to end, and why the CLI refused it. The CLI acknowledges any level, so a refusal is an error answer, such as from a CLI that doesn't know the request; the stored level stands either way. A relaunch starts without one and runs the stored effort (`--effort`).
The registry (`Agents::set_effort`) refuses a level the agent's current model doesn't take (`ModelList::effort_levels`): a running agent's model is the one its chat shows it set to, checked against the list cached for its launch, and a paused one's the one its next launch would run, against that launch's list. The chat shows it as `ChatEffort`: the level, the model's levels (none while the list isn't known, empty for a model that takes no effort), what Claude Code runs instead when the model doesn't take the level (`runs_as`: the nearest level below, the rule the pinned-CLI suite asserts; the stored level is kept), whether it's pending, and a refusal. An agent not running yet (paused, held, or still starting) shows what it will launch with, its model's levels from the list its launch would be offered (`present_stored_effort`), and a pick made while it's paused, of an effort or a model, shows again at once. A session worker restarting a crashed CLI launches it with the effort last acknowledged, as with the model.
