# The agent runtime

## Stopping a CLI

The session worker reports each CLI it spawns (`SessionEvent::Spawned`), identified by its pid and start time (`CliProcess`), since pids are reused; only a process matching both is ever signalled.
A forced stop, after the stop's grace, stops the CLI's whole process tree (`stop_tree`, over `devora-platform`'s process table): Claude Code makes each background shell a session and process-group leader of its own, so neither a process group nor a session reaches them, while the CLI's descendant tree does. A graceful stop is unchanged: the CLI exits by itself once its background work has ended.
`stop_tree` freezes the tree first (`SIGSTOP`, walking parent links until no new process turns up), then kills everything it collected, even when the walk fails part way. Its known limit: a descendant already reparented to launchd (or init) isn't found.
`StopInfo` reports whether a stop was graceful (the CLI exited by itself within the grace, whatever its exit code: it exits 1 after an interrupted turn) and whether it interrupted a turn.

## Background work

The CLI lists the agent's background tasks (background shells, `local_bash`, and subagents, `local_agent`) whenever the list changes (`System::BackgroundTasksChanged`), and `SessionHandle::stop_task` ends one through the CLI: its processes stop, with no model turn for a shell, while a stopped subagent makes the CLI run a notification turn of its own. The pinned-CLI suite asserts both, and that the interrupted turn runs no tool.

## The models the CLI offers

`models::decode` reads the `models` list of an initialize reply: each entry's `value` (what to pass and store; an alias such as `opus` follows the CLI to newer models), what it resolves to today, its display name and effort levels, plus the reply's `claude_code_version`. A real login's list has the aliases first, then full IDs of other models, older ones included; an API-key-only setup gets just the aliases.
Every model field shows it the core's way, in both apps: `ModelList::sections`, two sections with a label for each row. "Aliases" are the tiers Claude Code's aliases name, a tier Devora doesn't know first (alphabetically; `unknown_aliases`, which the model cache logs once each), then Fable, Opus, Sonnet and Haiku, each as "Opus (currently 5.5)": what it resolves to today, without repeating the tier's word, or its ID when Claude Code names it only by the tier (an API-key login). "Model IDs" are every model once by its version, those the aliases resolve to included, by major version (newest first), then tier, then version (newest first), an ID that doesn't read as `claude-<tier>-<major>[-<minor>]` last, alphabetically. Neither shows `IGNORED` (Claude Code's `default`, a choice rather than a model, and `opusplan`, which agents don't offer; `ccc`'s Default model setting still stores it). An agent's model is offered both sections; a model tier only the second. Typing narrows them by one rule for every field (`ModelSections::narrowed`): a tier by its own name, a model by its name or ID, and every row while the field holds exactly a value one of them stores.
`models::discover` gets that reply without a session: an initialize-only launch with the session's program, environment and settings (so the login and tier settings are an agent's), plus `--strict-mcp-config`, `--no-session-persistence` and `disableAllHooks`, so it starts none of the user's MCP servers, plugins' servers or hooks; closing its input ends it, and it leaves no session file. Not `--bare`, which ignores the OAuth login. The pinned-CLI suite proves all of that against a setup where a plain launch starts each one.
The core caches the list per profile (`devora-core`'s `agents::ModelOptions`, which the agent registry keeps and a host without agents, Ember's settings, keeps its own of): every agent start fills it from its `Ready` reply, logging the list at Info, and a UI's request probes only when the cache is a day old, from another CLI version, or from other launch settings (a changed model tier resolves the aliases differently). It runs one lookup at a time per profile and launch settings: callers asking meanwhile share it, a failure reaches them all, and the next call asks again. `ModelOptions::shutdown` ends the lookups under way (dropping one kills its CLI) and refuses new ones, waiting at most `MODEL_LOOKUP_GRACE`; the registry's shutdown and Ember's quit call it, so a quitting app leaves no CLI behind.

## The model replies come from

What answered is the `model` on each reply in the agent's own conversation (`Message::is_main_thread`): not the session's `init` (wrong under `opusplan` in plan mode), not a result's `modelUsage` (what was asked for, subagents included), and not `get_settings` or `get_context_usage` (the model set, even after a fallback). Replies Claude Code makes up itself are named `<synthetic>` (`protocol::is_model`): a turn it ends after failing, such as an overloaded model with no fallback, which is what a Devora agent gets, since Devora passes no `--fallback-model` and the CLI ignores `fallbackModel` in settings here. The pinned-CLI suite asserts both.
The transcript keeps each reply's model (`TranscriptContent::Assistant::model`) and adds a `SystemKind::ModelChanged` row where the agent's replies switch models, once per switch: worded by Claude Code's `model_fallback` when that announced it in the same turn (the fixtures' `claude-2.1.326/model-fallback.jsonl`), else "Model changed: A → B", with both IDs in its detail. `api_retry` and `model_fallback` add no row by themselves.
A conversation stored before replies kept their model continues from Claude's saved session (`session::saved_model`, the same reader as `saved_turn`): its main file holds only the agent's own replies, each with the model that answered, and a subagent's are saved apart, marked `isSidechain`.
`ModelList::name_of`, `resolve` and `expects` name a model and say whether a reply is what a setting runs under the profile's tiers (an alias through its entry, `opusplan` its Opus or Sonnet, a full ID itself; a setting the list can't resolve expects anything), comparing IDs through `same_model`, since the API answers an undated ID with its dated snapshot. A model the CLI doesn't name is shown by its ID, as it is.

## A turn Devora stopped

Claude Code ends an interrupted turn with an error result (`error_during_execution`, `is_error`, `terminal_reason: "aborted_streaming"`; the fixtures' `claude-2.1.312/interrupt.jsonl`). When Devora asked for the interrupt itself, the transcript words the result that follows "Turn stopped" and adds `"stopped": true` to its detail, so a UI shows it as the session's note, not as a failure. Devora asks for it (`Transcript::expect_stop`) on the user's Stop, recorded as an `Interruption` intention; on a pause cutting a stopped subagent's notification turn short; and before any pause of the session, which interrupts a running turn: the host's (`SpaceHandle::pause`, through the space actor's `ExpectStop`: a tab closing, a quit, a hold), the actor's own when its consumer goes away, and its stop after a failure. The next result spends it, and a session's end (or a new session) drops it, so a stop asked for never marks a later session's error. It rests on what Devora did, not on the CLI's reason strings. Any other error result is "Turn ended with an error".
